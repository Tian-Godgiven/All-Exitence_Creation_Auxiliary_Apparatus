# 时间线 TimeLine

## 现状总结（v0.1.0）

### 已实现

当前时间线是一个**线性刻度轴**：在一根横线上按时间值大小排列事件节点，支持拖拽平移和按钮缩放。

**数据层（完成度较高）：**
- 三种时间线类型已定义：事物（Exitence）、文章（Article）、事物属性（Status）
- 与自定义时间规则（customTime）的对接
- CRUD 操作、项目级持久化（`projects/{name}/data/timeLine.json`）
- 创建/编辑流程（选目标类型 → 选具体对象 → 选时间属性 → 选单位范围）

**渲染层（完成度低）：**
- SVG 直线 + 刻度，刻度根据进位层级调整粗细和长度
- 事件节点为 100x120px 的固定大小方块，奇偶交替排列在线上下
- pointerdown/move/up 拖拽平移，无惯性
- 按钮点击缩放，三阶段：调刻度值 → 调间距 → 切换时间单位

**未完成：**
- `Group.vue` 为空壳（拆分/合并功能未实现）
- `translateTime.ts` 中自定义时间的字符串翻译和时间差计算标注了"未完成"
- 属性类型时间线在编辑页面中已注释
- 已从 `supportAbilityList` 中注释掉，未上线

### 现有问题

1. **移动端体验差**：横向时间轴在移动端屏幕上空间不足，拖拽操作无惯性无回弹
2. **渲染过于简陋**：纯黑色方块和直线，缺少连接线、颜色区分、动画效果
3. **功能模型过于线性**：只能在一根等比例刻度轴上放点，无法表达非线性时间、并行时间段、时间间隔折叠等创作中常见的需求
4. **DOM/SVG 方案的性能瓶颈**：节点多时 DOM 数量膨胀，自由平移缩放体验不佳

## 重新设计（v2）

### 设计目标

从"线性刻度轴"升级为**时间关系图**——一个带有时间概念的思维导图。

核心需求：
1. **非线性时间**：两个时间段之间可以存在折叠的时间间隔（如"~~~7天后~~~"），不需要按比例画出
2. **多轨道并行**：主线和支线可以同时存在，彼此之间有"同时发生"等关系
3. **异构时间单位**：不同时间段可以用不同的时间规则和精度（如一个段按小时、另一个按天、甚至用不同历法）
4. **宏观 + 微观**：有宏观大时间轴把所有东西串起来，也可以深入某个段查看细节
5. **可交互**：节点可点击、拖动、连线、编辑，类似思维导图的操作体验

### 概念模型

```
MacroTimeLine（宏观时间线 / 画布）
├── Segment（时间段）
│   ├── 有自己的时间规则（TimeRule）
│   ├── 有自己的精度/单位级别
│   └── Block[]（事件块，按段内时序排列）
│       └── 指向事物（Exitence）或文章（Article）
├── Connection（段间连接）
│   ├── after：时间间隔（"7天后"）
│   ├── parallel：并行（"同时发生"）
│   └── branch：分支（"从某处分出"）
└── 画布状态（视口位置、缩放等）
```

**使用场景示例：**

```
══════════ 宏观时间线（画布） ════════════════════════════

 ┌─ 第一章·日常 ─┐   ~~3个月后~~   ┌── 第二章·决战 ──┐
 │ 单位：天       │                │ 单位：小时       │
 │               │                │                 │
 │ Day1: 入学    │                │ 14:00 集结      │
 │ Day3: 相遇    │                │ 15:30 开战      │
 │ Day7: 事件X   │                │ 18:00 结束      │
 └───────────────┘                └─────────────────┘
                                         │
                                    「同时发生」
                                         │
                               ┌── 支线·逃亡 ──┐
                               │ 使用异国历法    │
                               │ 雨月3日: 出逃  │
                               │ 雨月5日: 到达  │
                               └───────────────┘
```

### 数据结构（草案）

#### MacroTimeLine 宏观时间线

每个项目可以有多条宏观时间线，保存在 `projects/{name}/data/timeLine.json` 中。

```typescript
type MacroTimeLine = {
    name: string
    segments: Segment[]
    connections: Connection[]
    viewport: {
        x: number              // 画布视口位置
        y: number
        scale: number          // 缩放比例
    }
    __key: string
}
```

#### Segment 时间段

一个有内部时序的容器，拥有独立的时间规则和精度。

```typescript
type Segment = {
    name: string
    timeRule: TimeRule             // 这个段用什么历法（"date" 或自定义规则的 key）
    unitLevel: string             // 这个段的精度（"小时" / "天" / "月" 等）
    blocks: Block[]               // 内部的事件块，按段内时序排列
    position: { x: number, y: number }  // 在画布上的位置
    collapsed: boolean            // 是否折叠（折叠时只显示名称）
    setting: Record<string, any>
    __key: string
}
```

#### Block 事件块

时间段内的具体事件，指向项目中的事物或文章。

```typescript
type Block = {
    time: number                  // 段内的时间值
    label: string                 // 显示标签（可自动生成或手动填写）
    target: ExitenceRef | ArticleRef | null  // 指向的对象（可选）
    __key: string
}

// 引用类型
type ExitenceRef = {
    type: "exitence"
    typeKey: string
    exitenceKey: string
    statusKey?: string            // 可选：关联的时间属性
}

type ArticleRef = {
    type: "article"
    from: string[]
    articleKey: string
    timeField: "createTime" | "updateTime"
}
```

#### Connection 段间连接

描述两个时间段之间的时间关系。

```typescript
type Connection = {
    from: string                  // 源 Segment 的 key
    to: string                    // 目标 Segment 的 key
    type: "after"                 // 时间间隔：A 发生在 B 之后
        | "parallel"              // 并行：同时发生
        | "branch"                // 分支：从某处分出
    gap?: {                       // type 为 "after" 时
        value: number
        unit: string              // 间隔的单位
        timeRule: TimeRule         // 间隔使用的时间规则
        display?: string          // 自定义显示文本，如 "三个月后"
    }
    __key: string
}
```

### 渲染方案

#### 技术选型：Canvas 2D

参考项目 [project-graph](https://github.com/graphif/project-graph)（同为 Tauri 应用，MIT 协议），采用 Canvas 2D 渲染，理由：

1. **性能**：大量节点和连线时，Canvas 比 DOM/SVG 快得多
2. **自由度**：自由平移缩放、惯性滑动、任意连线绘制，Canvas 原生支持
3. **移动端适配**：Canvas 上的触摸手势（平移、双指缩放）比 DOM 拖拽更顺滑

#### 需要实现的基础设施

参考 project-graph 的架构：

1. **Camera（相机系统）**
   - 世界坐标 ↔ 屏幕坐标变换
   - 拖拽平移（带惯性/摩擦力）
   - 双指/滚轮缩放（以焦点为中心）
   - 平滑过渡动画

2. **Renderer（渲染器）**
   - 分层渲染：背景网格 → Segment 容器 → Block 节点 → Connection 连线 → 交互层
   - 视锥裁剪（只渲染可见区域）
   - HiDPI 适配

3. **交互系统**
   - 节点选择、拖拽
   - 连线创建
   - 双击编辑
   - 右键/长按菜单

#### 可选方案：使用 Canvas 库

为降低开发成本，可以考虑使用 Canvas 库而非从零实现：
- **Konva**（有 `vue-konva` 封装）：提供事件系统、图层、拖拽等基础能力
- 或者直接参考 project-graph 的 Camera + Renderer 代码自行实现

### 交互设计（待细化）

#### 基础操作
- 单指/鼠标拖拽画布：平移视口
- 双指捏合/滚轮：缩放
- 点击 Segment：展开/折叠
- 点击 Block：显示对应事物/文章的详情弹窗
- 长按 Block：拖拽排序或移动到其他 Segment

#### Segment 操作
- 创建新时间段
- 编辑时间段（名称、时间规则、精度）
- 在段内添加/删除 Block
- 拖拽调整段的位置

#### Connection 操作
- 从一个 Segment 拖线到另一个 Segment，创建连接
- 选择连接类型（之后/并行/分支）
- 编辑时间间隔（after 类型）

### 与世界线功能的关系

参见 `世界线.md`。世界线功能可以视为宏观时间线的一个上层概念：在不同"世界线"下切换不同的 MacroTimeLine，用于平行世界、if线等创作场景。

```
世界线管理
├── 世界线A（正史线）→ MacroTimeLine
├── 世界线B（if线）  → MacroTimeLine
└── 世界线C（前传）  → MacroTimeLine
```

## 方案对比：Segment 容器 vs Graph 图

在重新设计的过程中产生了两个方案，各有取舍，记录在此以供后续决策。

### 方案 A：Segment 容器模型

即上面「重新设计」一节描述的方案。核心思路是**容器套节点**：

```
MacroTimeLine
├── Segment（时间段容器，各有独立时间规则和精度）
│   └── Block[]（段内事件，按时序排列）
└── Connection（段与段之间的关系）
```

**优势：**
- 结构清晰，天然为事件提供了分组归属
- Segment 可折叠，适合在宏观视角下快速概览
- 段内事件可以共享时间规则和精度，减少配置

**劣势：**
- 事件必须归属于某个 Segment，边界划分可能困扰用户
- Segment 之间移动事件需要容器间迁移逻辑
- Segment 本身的自动排列和尺寸计算增加了复杂度
- 两层结构（容器 + 节点），数据模型和交互都更复杂

### 方案 B：Graph 图模型（Block 即节点，间隔即连线）

把时间线视为一个**有向图 / 思维导图**：

```
[入学] ——1天后——> [相遇] ——4天后——> [事件X] ————3个月后————> [集结] ——1.5h——> [开战]
                                                            │
                                                        「同时」
                                                            │
                                                         [出逃] ——2天——> [到达]
```

核心思路：
- **节点** = 事件（Block）
- **边** = 时间关系（间隔、并行、分支……）
- 有一个**主轴方向**（用户可选横/竖），沿主轴 = 时间先后，垂直于主轴 = 并行/同时
- 不强求等比例，所有时间间隔都是显式标注在边上

**优势：**
- 数据模型更简单——只有节点和边，没有容器层
- 没有归属问题——每个事件是独立节点
- 异构时间单位天然解决——时间信息挂在边上，每条边可以用不同的单位甚至不同历法
- 非线性时间是默认的——不存在等比例刻度轴
- 分支/并行是图的自然表达

**劣势：**
- 纯图结构太自由，用户可能摆得很乱——需要主轴方向约束 + 可能的自动布局辅助
- 没有分组概念，大量事件时缺少层次感——可通过视觉手段（颜色、区域框选）弥补
- 缩放到宏观时，纯节点图可能不如 Segment 的折叠效果直观

**数据结构：**

```typescript
// 整个时间线画布
type TimeLineGraph = {
    name: string
    blocks: Block[]
    connections: Connection[]
    direction: "horizontal" | "vertical"  // 主轴方向
    viewport: { x: number, y: number, scale: number }
    __key: string
}

// 事件节点
type Block = {
    label: string
    target?: ExitenceRef | ArticleRef    // 可选：关联到事物/文章
    position: { x: number, y: number }   // 画布上的位置
    __key: string
}

// 连接
type Connection = {
    from: string                         // Block 的 key
    to: string                           // Block 的 key
    type: "after" | "parallel" | "branch"
    gap?: {
        value: number
        unit: string                     // "小时" / "天" / "雨月" 等
        timeRule?: string                // 使用的时间规则 key
        display?: string                 // 自定义显示文本
    }
    __key: string
}
```

### 方案 C（混合）：图模型 + 可选分组框

也可以考虑以方案 B 的图模型为基础，加入一个轻量的"分组框"功能（类似 Figma 的 Frame 或 project-graph 的 Section）：

- 底层是图模型，Block 之间通过 Connection 连接
- 用户可以拖拽画出一个矩形区域，为区域内的 Block 命名（如"第一章·日常"）
- 分组框只是视觉标注，不影响数据关系——Block 不"属于"分组框
- 分组框可以折叠为一个节点，展开后显示内部的 Block

这样兼顾了图模型的灵活性和容器模型的可读性。

### 倾向

目前倾向**方案 B 或 C**。方案 A 的 Segment 容器在数据模型上带来了不必要的复杂度，而方案 B 的图模型更贴合"有时间轴的思维导图"这个初始设想。方案 C 是方案 B 的渐进增强，可以在方案 B 落地后再考虑是否需要。

## 开发路线（建议）

无论选择哪个方案，Phase 1 都是相同的，可以先做起来，推迟方案选择的决策点。

### Phase 1：Canvas 基础设施（方案无关）
- 实现 Camera 系统（平移、缩放、惯性、触摸手势）
- 实现基础 Renderer（背景网格、矩形、文本、连线绘制）
- 世界坐标 ↔ 屏幕坐标变换
- HiDPI 适配、视锥裁剪
- 参考 project-graph 的实现，或评估 Konva / vue-konva 的可行性

### Phase 2：节点 + 连线的基础渲染与交互
- Block 渲染为可点击的事件卡片
- Connection 渲染为带标签的有向连线
- 节点拖拽移动
- 点击 Block 联动到事物/文章详情弹窗

### Phase 3：时间关系的完整表达
- after 类型连线：显示时间间隔文本（支持不同单位和历法）
- parallel 类型连线：垂直于主轴方向的视觉表达
- branch 类型连线：分叉视觉效果
- 主轴方向切换（横/竖）

### Phase 4：编辑功能
- 在画布上直接创建 Block
- 拖拽创建 Connection，选择类型和间隔
- Block 关联到现有的事物/文章数据
- 删除、修改节点和连线

### Phase 5：增强功能
- （若采用方案 C）可选分组框：框选区域命名，折叠/展开
- 自动布局辅助（沿主轴方向自动排列）
- 搜索定位（按事物/文章名称跳转到对应节点）
- 与自定义时间规则（customTime）的深度对接
- 世界线切换（多条 TimeLineGraph 之间的管理）
- 导出/分享
