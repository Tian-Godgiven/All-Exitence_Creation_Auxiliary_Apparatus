# 拖拽排序系统

## 现状

### 当前方案：Atlaskit Pragmatic Drag and Drop

当前使用 `@atlaskit/pragmatic-drag-and-drop` + `@atlaskit/pragmatic-drag-and-drop-hitbox` 实现拖拽排序。

在此基础上封装了以下内容：

| 文件 | 作用 |
|------|------|
| `api/dragToSort.ts`（~290行） | 封装了 getDraggable / getDroppable / getCombine / getMonitor |
| `components/global/Draggable.vue` | 通用可拖拽组件，包含边缘指示器和预览幻影 |
| `components/other/DraggableList.vue` | 传入列表自动生成可排序列表 |
| `components/other/DragNode.vue` | DraggableList 的子节点组件 |
| `components/other/indicator.vue` | 拖拽时的插入位置指示线 |

### 实际使用场景

- 左侧面板中分类/事物/章节的列表排序
- 弹窗里属性列表的排序
- 标签组排序

本质上都是**纵向列表内的拖拽排序**，最多加上章节的树形嵌套（`allowInto` + `level`）。

## 存在的问题

### 1. 库与需求不匹配

Pragmatic DnD 是为桌面端复杂场景设计的（Jira 看板、Trello 等），提供了 `attachClosestEdge`、`extractInstruction`、`reorderWithEdge` 等大量概念。对于本项目的纵向列表排序需求来说，抽象层级过高，引入了不必要的复杂度。

### 2. 移动端兼容性

Pragmatic DnD 的核心基于原生拖拽 API（`draggable`、`dragstart`、`drop`），在移动端 WebView 上支持参差不齐。虽然做了 pointer event 兼容，但"拖起 → 悬停 → 放下"的交互模式在触屏上不够自然。

### 3. 封装本身比库调用更复杂

`dragToSort.ts` 有 290 行，加上 4 个组件，这套封装的复杂度已经超过了库的直接调用。而且存在以下代码问题：

**a) DraggableList 的 key 使用了 Symbol()**

```html
<DragNode v-for="item,index in list" :key="Symbol()">
```

每次渲染都生成新的 Symbol()，Vue 永远认为这些是新节点，完全失去虚拟 DOM diff 优化——列表变化时所有子组件被销毁重建。应使用 item 的 `__key` 作为 key。

**b) 重复注册无法清理**

```typescript
// getDraggable 中：
if(element.draggable == true) return;  // 已注册则返回 undefined
```

`getCombine` 收到 undefined 后返回空函数 `()=>{}`，之前注册的监听器永远不会被清理。

**c) cleanup 逻辑不完整**

`Draggable.vue` 在 handler 为 undefined 且使用 watch 时，cleanup 只在 `onUnmounted` 中调用一次，但 watch 可能触发多次 getCombine，前几次的 cleanup 会丢失。

### 4. 与项目中其他触摸系统冲突

项目已有 `vue3-touch-events`、手写的 pointer event 页面滑动、floatButton 拖拽等触摸处理。再加一套 Pragmatic DnD 的拖拽体系，事件冲突和优先级难以管理。

## 迁移建议：SortableJS（vuedraggable）

### 理由

1. **已经安装了**：`package.json` 中已存在 `vuedraggable` 依赖（基于 SortableJS），但当前未使用
2. **移动端友好**：SortableJS 原生支持触摸拖拽，不依赖浏览器的原生拖拽 API
3. **极大简化代码**：290 行封装 + 4 个组件 → 几乎为零的封装代码
4. **减少依赖**：可移除 `@atlaskit/pragmatic-drag-and-drop` 和 `@atlaskit/pragmatic-drag-and-drop-hitbox`

### 基础用法

```vue
<draggable v-model="list" item-key="__key" handle=".drag-handle">
  <template #item="{ element }">
    <div>
      <span class="drag-handle">☰</span>
      {{ element.name }}
    </div>
  </template>
</draggable>
```

### 树形嵌套

SortableJS 支持嵌套 `<draggable>` 实现跨层级拖拽，可替代当前的 `allowInto` + `level` 方案。配置比扁平列表多一点，但比 `attachInstruction` + `extractInstruction` 简单得多。

### 迁移步骤

1. 在一个简单的列表（如标签组排序）上先用 vuedraggable 替换，验证移动端体验
2. 逐步替换其他使用 Draggable / DraggableList 的地方
3. 最后处理章节的树形拖拽
4. 全部替换后移除 `@atlaskit` 依赖和 `dragToSort.ts` 等文件
