# 项目仓储设计

## 目的

项目仓储层集中管理本地路径、JSON 编解码、格式版本、原子写入、保存串行化和回收站目录操作。

界面、领域操作与辅助功能不再自行拼接 `data/projects/...` 路径或直接调用 Tauri 文件 API。

```text
界面 / 弹窗
      ↓
领域操作（创建、编辑、移动、删除）
      ↓
项目状态服务
      ↓
ProjectRepository
      ↓
Tauri 文件系统
```

仓储层不负责 Vue 响应式状态、弹窗提示或业务规则；它只读写数据并返回成功结果或可处理的错误。

## 第一批接口

```ts
interface ProjectRepository {
  initializeApp(): Promise<AppData>
  saveApp(app: AppData): Promise<void>

  listProjects(): Promise<ProjectSummary[]>
  createProject(project: ProjectData): Promise<void>
  loadProject(projectKey: string): Promise<ProjectData>
  saveProject(project: ProjectData): Promise<void>

  moveProjectToTrash(projectKey: string): Promise<TrashRecord>
  restoreProject(trashRecordKey: string): Promise<void>
  permanentlyDeleteProject(trashRecordKey: string): Promise<void>

  loadFeature<T>(projectKey: string, featureKey: string): Promise<T | null>
  saveFeature<T>(projectKey: string, featureKey: string, data: T): Promise<void>
  removeFeature(projectKey: string, featureKey: string): Promise<void>
}
```

`ProjectData` 聚合 `project.json`、`articles.json` 与 `exitence.json` 的内存数据；一次 `saveProject` 进行核心文件全量保存。辅助功能文件通过独立接口保存，避免未知的辅助功能数据混入核心模型。

## 内部职责

1. 根据项目 `__key` 生成路径，项目名称不参与路径。
2. 验证每个核心文件的 `formatVersion`。
3. 读取核心文件时区分缺失、格式错误、版本不支持与文件系统错误。
4. 使用临时文件写入、替换正式文件，并确保同项目保存请求串行。
5. 管理活跃项目目录与应用级回收站之间的移动、恢复和永久删除。
6. 为辅助功能提供统一路径与文件读写能力。功能默认数据和重置逻辑由功能自身定义，避免仓储层依赖具体功能。

## 迁移步骤

1. 新增仓储的数据类型、路径规则与文件系统适配层，不接入现有运行流程。
2. 用新格式创建、读取和保存一个空项目，验证目录与 JSON 结构。
3. 将项目创建、加载、保存、改名与删除逐项切换到仓储层。
4. 将文章和事物的业务操作与直接文件读写解耦。
5. 逐个迁移已启用辅助功能；每迁移一个即验证其创建、切换项目、保存和损坏文件重置流程。
6. 在新格式稳定后提供开发期应用数据重置工具。

## 第一项实现边界

第一项代码改动只创建仓储层的目录、类型和路径规则，不修改现有 `hooks/fileSysytem.ts`、项目流程或辅助功能，也不创建、移动或删除用户数据。现有应用保持继续使用旧读写逻辑。
